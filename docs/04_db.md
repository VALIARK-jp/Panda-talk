### match_scores
```sql
PRIMARY KEY         (user_a_id, user_b_id)
user_a_id           UUID REFERENCES users(id)
user_b_id           UUID REFERENCES users(id)
match_rate          FLOAT NOT NULL       -- 0.0 ~ 1.0 （インデックス用に保持）
common_answer_count INT NOT NULL
same_answer_count   INT NOT NULL
updated_at          TIMESTAMP DEFAULT NOW()

CHECK (user_a_id < user_b_id)   -- UUIDの大小で順序固定 → 1ペア1レコード保証
```

**更新時:** `same_answer_count` と `common_answer_count` を+1し、`match_rate = same / common` を再計算して保存

**設計方針:**
- ユーザーペアごとに1レコード（nC2件）
- 共通回答が0問のペアはレコードを作らない
- マッチ画面は単純な `SELECT ... ORDER BY match_rate` で取得できる

**更新タイミング（インクリメンタル更新）:**
- ユーザーAが問題Qに回答した瞬間に、問題Qに回答済みの全ユーザーとのスコアを差分更新
- バッチ再計算は不要

**レコード数の目安:**
| ユーザー数 | 最大レコード数（実際はもっと少ない） |
|---|---|
| 1,000人 | 約50万 |
| 10,000人 | 約5,000万 |

※ 共通回答がないペアはレコードなしなので実際はnC2より大幅に少ない

### groups
```sql
-- ENUM定義
CREATE TYPE group_type AS ENUM ('high_match', 'middle_match', 'low_match');

id          UUID PRIMARY KEY
name        TEXT NOT NULL
type        group_type NOT NULL
created_at  TIMESTAMP DEFAULT NOW()
```

**グループ種別:**
| type | 概要 | 人数 |
|---|---|---|
| high_match | 全ペアの合致度が高い | 3人 |
| middle_match | 全ペアの合致度が50%付近 | 3人 |
| low_match | 全ペアの合致度が低い（真逆） | 3人 |

**グループ成立条件:** 3人全ペア（3C2=3組）が該当の合致度範囲に収まっていること

### comments
```sql
id          UUID PRIMARY KEY
question_id UUID REFERENCES questions(id)
user_id     UUID REFERENCES users(id)
choice      answer_choice NOT NULL  -- どっち派のコメントか
body        TEXT NOT NULL
created_at  TIMESTAMP DEFAULT NOW()
```

**設計方針:**
- 表示時はuser_idを出さず匿名表示
- choiceで「a派のコメント」「b派のコメント」に分けて表示できる
- 1ユーザーが同じ問題に複数コメント可能（制限するなら UNIQUE (question_id, user_id) を追加）

### question_likes
```sql
PRIMARY KEY   (user_id, question_id)
user_id       UUID REFERENCES users(id)
question_id   UUID REFERENCES questions(id)
created_at    TIMESTAMP DEFAULT NOW()
```

**設計方針:**
- いいね数は `SELECT COUNT(*) FROM question_likes WHERE question_id = ?` で集計

**設計方針:**
- いいね数は `SELECT COUNT(*) FROM comment_likes WHERE comment_id = ?` で集計
- コメント一覧取得時にいいね数も一緒に返す

### notifications
```sql
-- ENUM定義
CREATE TYPE notification_type AS ENUM (
  'like',            -- 自分の質問にいいねされた
  'comment',         -- 自分の質問にコメントされた
  'friend_request',  -- 友達申請が来た
  'friend_accepted', -- 友達申請が承認された
  'new_match',       -- 高合致ユーザーが現れた
  'group_created'    -- グループに追加された
);

id          UUID PRIMARY KEY
user_id     UUID REFERENCES users(id)   -- 受信者
actor_id    UUID REFERENCES users(id)   -- 通知を起こしたユーザー（NULLはシステム通知）
type        notification_type NOT NULL
target_id   UUID                        -- 対象レコードのID（question_id / group_id など）
is_read     BOOLEAN DEFAULT FALSE
created_at  TIMESTAMP DEFAULT NOW()
```

**設計方針:**
- 未読件数は `SELECT COUNT(*) WHERE user_id = ? AND is_read = false`
- 既読化は `UPDATE SET is_read = true WHERE user_id = ? AND is_read = false`
- actor_idがNULLの場合はシステム通知（グループ自動生成など）

## インデックス設計（重要）

```sql
-- 合致度の高速検索
CREATE INDEX idx_match_scores_user_a ON match_scores(user_a_id, match_rate DESC);
CREATE INDEX idx_match_scores_user_b ON match_scores(user_b_id, match_rate DESC);

-- 回答の検索
CREATE INDEX idx_answers_user_id ON answers(user_id);
CREATE INDEX idx_answers_question_id ON answers(question_id);

-- いいね数集計
CREATE INDEX idx_question_likes_question_id ON question_likes(question_id);
CREATE INDEX idx_comment_likes_comment_id ON comment_likes(comment_id);

-- お知らせの未読取得
CREATE INDEX idx_notifications_user_id_unread ON notifications(user_id, is_read);
```

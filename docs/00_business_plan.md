## 0. エグゼクティブサマリー

パンダトークは、**二択質問に答え続けることで価値観が可視化され、合致度で人とつながる** SNSである。

| 項目 | 内容 |
|---|---|
| サービス名 | パンダトーク |
| カテゴリ | 価値観マッチングSNS |
| コンセプト | 白黒つけるほど、仲良くなるSNS。 |
| 初期ターゲット | 大学生（阪大からスタート想定） |
| クライアント | Flutter（iOS / Android / Web ビルド可） |
| API | Hono + TypeScript（Cloudflare Workers） |
| データ | Supabase（PostgreSQL + Auth + Storage） |

**プロダクトの二層構造（現行）**

1. **オンボーディング:** 全ユーザー共通の **16問 16type 診断**（運営シードの Q1–16）→ パンダタイプ・4軸％・結果モーダル
2. **本編:** ユーザー投稿の **無限二択フィード**（Q17 以降＋未回答フロンティア）→ 合致度・マッチ・友達・コメント

MBTI の固定診断アプリではなく、「診断でフック → 無限質問 SNS」が差別化の芯。

---

## 1. ビジョン

### 「人間関係の検索エンジンを作る」

既存 SNS は見た目・フォロワー数・写真でつながる。パンダトークは **感覚・価値観・思考** を軸にする。

### 最終目標

> 「この人、自分とめっちゃ合う」を世界で一番自然に発見できるプラットフォームを作る。

---

## 2. ポジション・差別化

| 比較軸 | MBTI / 診断アプリ | X / Instagram | パンダトーク（現行） |
|---|---|---|---|
| 質問 | 固定 | タイムライン投稿 | **16問固定＋その後ユーザー生成で無限** |
| タイプ | 16種固定 | なし | **16type＋回答が増えるほどプロフィールが更新** |
| 中心体験 | 結果を見る | 発信・いいね | **答える → 比率を見る → 合致度で人を見る** |
| 関係性 | 弱い | フォロー | **友達（相互）・マッチ・DM（実装済み、UI は一部非表示）** |

- ❌ 診断アプリで終わらない（16問は入口）
- ✅ 回答データが溜まる SNS
- ✅ 白黒 UI で「どっち派」が一瞬で伝わる

## 3. いまのプロダクト状態（スナップショット）

マーケ・UI 最適化の前提として、**2026-05-21 時点でアプリに載っているもの**を整理する。

### 3.1 リリース可能な体験の流れ

```
オンボーディング（ゲスト可）
  → 診断タブで Q1–16 回答（進捗バー・診断完了表示）
```

## 6. コア機能の仕様（実装ベース）

### 6.1 回答 UI（診断タブ）

**回答前:** 左右 50/50 の二択ボタン（白＝A / 黒＝B）、パルスアニメーション。

**回答後:**

1. ボタンが白黒比率バーに morph（約 750ms）
2. 上段: 選択肢ラベル + **その側の％**（自分の選択側を強調）
3. バー内: 「君の選択」マーカー
4. **1.5 秒後**に次の未回答へ自動スクロール
5. 上方向スワイプで過去問へ（回答済みは閲覧・再回答不可）

**集計ルール（少数派 / 異端児）**

- その問の総回答 1 件のみ → 多数派扱い（スコアに効かない）
- 同票 → どちらも多数派
- それ以外 → 選んだ側の票数が少ない方が少数派
- 後から他ユーザーが答えると、過去の自分の判定が変わりうる

### 6.2 フィード取得ロジック

| モード | API | 表示 |
|---|---|---|
| 診断中 | `GET /questions/window?maxQuestionNumber=16` | 回答済み + 次の 1 問まで |
| 診断後 | `GET /questions/window`（before/after） | 未回答フロンティア前後 |
| Hot タブ（現状） | 上記と同じリスト | **percentA 降順で並べ替えのみ** |

### 6.3 コメント（集中モード）

- コメントアイコン → Hero で比率バーが上部へ
- 質問文 + A 派 / B 派の **2 カラム**
- 自分が答えた側のみコメント投稿可

### 6.4 合致度・マッチ

```
match_rate = 同じ回答数 / 共通回答数
display_score = match_rate × (共通数 / (共通数 + 50))  // 信頼度補正
```

表示: 似ている人 / 真逆な人 / 50%付近（マッチ画面 3 タブ）

### 6.5 友達

- 相互承認のみ（申請 → 承認 / 拒否）
- フォロー機能は未実装

### 6.6 16type 診断

- Q1–16 の A/B が 4 軸の％にマッピング（[15_16type_questions.md](./15_16type_questions.md)）
- 16 スラッグ（例: ふしぎぱん）とキャラ・キャッチコピー
- プロフィール: 16type 枠内に自己紹介、「{名前}の傾向」で 4 軸の過半数表示

## 7. ブランド・UI（マーケ・最適化用）

### トーン

**可愛い × スタイリッシュ × 白黒** — カラフルにしない。余白・丸み・パンダで親しみ。

### カラーパレット（実装）

| 名前 | コード |
|---|---|
| Black | `#111111` |
| White | `#FFFFFF` |

| Border Gray | `#E5E5E5` |

| Like Red | いいね時のみ |

### UI ルール

- 白背景・黒文字・選択時のみ黒塗り
- 二択は **左白 / 右黒** で固定
- アクセントカラーは原則使わない（いいね赤など例外）

### マーケ素材との対応（参考画像）

LP 案の「3秒で答える」「16タイプ」「みんなの回答 62%」は、いまのアプリで言うと:

- **3秒で答える** → 二択タップ + morph（実装済み）
- **16タイプ** → 初回 16 問 + 結果モーダル（実装済み）
- **みんなの回答 62%** → ラベル下％ + バー（実装済み。別画面の大きな円グラフは未実装）

## 13. マーケ・UI 最適化で優先すべきギャップ

コードと事業計画の差分から、**次に手を入れると効果が大きい項目**。

| 優先度 | 項目 | 理由 |
|---|---|---|
| 高 | Hot タブを `/questions/hot` に接続 | 仕様と実装のズレ。盛り上がり質問の発見体験 |
| 高 | 16 問完了 → Q17 への遷移をマーケと同じ言葉で説明 | いま「診断完了」で止まって見えるユーザーがいる |
| 高 | LP / TikTok 用キャプチャとアプリ画面の一致 | 円形 62% など、別 UI は「Coming」かアプリ側に寄せる |
| 中 | トークタブの公開タイミング | 友達・DM まで作っているが入口がない |
| 中 | 回答結果の「みんなの回答」強調 | 別画面 `AnswerResultScreen` はあるがフィードはインライン |
| 中 | Web: LINE スキップ・ゲスト導線 | `MissingPluginException` 対策 |
| 低 | フォロー vs 友達の仕様整理 | ドキュメントからフォロー記述を削除するか実装するか |
| 低 | Google ログインの再開 | 非表示のままか |

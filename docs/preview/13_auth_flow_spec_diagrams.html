マルチアプリ前提とデータの分け方

Valiark では1 Supabase プロジェクトに複数アプリ（Panda Talk、Who eats など）を載せます。 auth.users は全アプリで共有し、「同じ人」は原則同じ UUID（auth.users.id）の1行に収めます（LINE は共通チャンネル・同一 line-auth-native 解決ルールなど）。 アプリ固有の名前・アバター・ドメイン進行はアプリ別プロフィール表（例: panda_profiles、whoeats_profiles）に id = auth.users.id でぶら下げます。

flowchart TB subgraph shared [共有 Supabase 1 プロジェクト] AU[(auth.users)] end subgraph profiles [アプリ別テーブル例] PP[panda_profiles] WP[whoeats_profiles] end AU -->|PK 同一 UUID| PP AU -->|PK 同一 UUID| WP

実際のテーブル名・migration は各アプリ／docs/12_multi_app_supabase.md に従う。

シナリオ: 同一 LINE アカウントでアプリA → アプリB

前提: 両アプリが同じ Supabase URL・anon key、同じ LINE チャンネル、同じ line-auth-native を参照している（運用違反で別チャンネル／別 Edge ロジックにすると、同じ人で auth.users が二重化しうる）。

ふつうに期待される流れ（1人1 auth 行・プロフィールだけアプリ別）

sequenceDiagram autonumber participant U as 利用者 participant PA as アプリA Panda Talk participant PB as アプリB Who eats participant LN as LINE participant EF as line-auth-native participant GT as GoTrue Note over U,GT: 1) アプリAで初回（新規登録 flow=signup） U->>PA: LINE 新規登録 PA->>LN: ログイン LN->>PA: accessToken PA->>EF: flow signup + token EF->>GT: line_id 未登録なら createUser 等 EF->>PA: hashed_token + otp PA->>GT: verifyOTP GT->>PA: session 確立 auth UUID 例 X PA->>PA: POST users/me 等で panda_profiles 用レコード Note over U,GT: 2) 同じLINEでアプリBへ（同じUUID X でセッション） U->>PB: LINE ログイン or 新規 PB->>LN: ログイン LN->>PB: accessToken 同一 LINE UID PB->>EF: flow login or signup + token EF->>GT: get_user_by_line_id ヒット UUID X EF->>PB: hashed_token PB->>GT: verifyOTP GT->>PB: session 同じ UUID X PB->>PB: ensure users/me whoeats_profiles 行を別途作成

アプリB の画面で「新規登録」を押しても、Edge 上では既に line_id が紐づいていれば新しい auth 行は作らず、同じ auth.users に対してマジックリンク検証だけ行う想定。初回だけ whoeats_profiles が無ければバックエンドが作る。

シナリオ: ログイン画面から LINE・未だ auth にいない

flow=login のとき、LINE UID が auth.users 側にまだ無いと Edge はユーザーを作らず 404 account_not_found を返す。画面は「新規登録から同じ方法で」と案内する。

sequenceDiagram participant U as 利用者 participant App as アプリ ログイン画面 participant EF as line-auth-native U->>App: LINE ログイン App->>EF: flow login + token EF->>EF: get_user_by_line_id なし EF->>App: 404 account_not_found App->>U: 新規登録へ誘導メッセージ

シナリオ: identity_conflict（別の LINE ID が既に同じメールユーザーに）

メールで既存ユーザーを引き当てて LINE を紐づけようとしたが、すでに別の line_id が app_metadata に付いている場合は 409。なりすまし連結を拒否する。

sequenceDiagram participant App as アプリ participant EF as line-auth-native EF->>EF: get_user_by_email ヒット EF->>EF: 既存 line_id と今回の UID が不一致 EF->>App: 409 identity_conflict + details App->>App: details を画面表示

シナリオ: メールでアプリA登録済み → アプリBで同じメール「新規」

auth.users はプロジェクト横断でメール一意。アプリB のメール新規フォームで同じアドレスを使うと GoTrue が既に登録と返す。Panda Talk クライアントは EmailAlreadyRegisteredException などでログイン画面へ誘導する想定（プロバイダが違っても同じアカウント基盤）。

flowchart LR A1[アプリAでメール新規] --> AU[(auth.users に1行)] AU --> A2[アプリBで同メール新規試行] A2 --> GT[GoTrue 重複エラー] GT --> UI[UI: ログインへ誘導]
